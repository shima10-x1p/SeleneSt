# 記録様式

## 候補：`.agent-improvement/candidates/YYYYMMDD-short-name.md`

```markdown
# 候補名

- 状態：候補
- 適用範囲：プロジェクト名と作業条件。
- 観測：何が起きたか。参照できる証拠と日付。
- 原因の仮説：事実と分ける。不明なら不明と記す。
- 提案：どのファイルの何を変えるか。
- 再利用場面：次にいつ使うか。
- 既存との差分：既存の指示や道具で足りない点。
- 確認方法：適用機会・利用実績・手戻り・副作用の見方。
- 試行結果：未実施。実施後は作業ごとの証拠を追記する。
```

採用・却下時は同じファイルを `decisions/` へ移し、次を追加する。

```markdown
- 判断：採用／却下／取り消し、日付、ユーザー指示の要約。
- 反映先：実際のファイルへの相対リンクと変更箇所。
- 適用時の検証：実施した確認と結果。
- 効果：未確認／効果あり／効果なし／悪化。根拠も記す。
- 戻し方：当該変更を特定できる説明。存在すればcommitも記す。
```

## 導入時のREADME

```markdown
# エージェントの改善記録

候補は通常作業の指示ではありません。振り返り・試行・採用・確認・却下・取り消しを明示的に依頼して運用します。

- candidates/：未採用の改善案。振り返り・試行・採用判断のときだけ読みます。
- decisions/：採用・却下・取り消しの根拠。通常作業では一括で読みません。
- active.md：採用済みの変更先と適用条件。規則の本文は一覧に転記せず、確認や変更は各項目からリンクしたファイルで行います。

新規候補は1回最大3件、0件も正常です。採用はユーザーが判断し、効果は次の実作業で確認します。
```

## 導入時のactive.md

```markdown
# 採用済みの改善

今回の作業に関係する適用条件の項目だけ参照してください。規則本文は反映先にあります。

| 改善 | 適用条件 | 反映先 | 判断記録 |
| --- | --- | --- | --- |
```

## AGENTS.mdへの導線

```markdown
## 作業からの改善

作業開始時は `.agent-improvement/active.md` があれば確認し、今回に関係する反映先だけ読む。候補と判断履歴は通常の作業指示として読まない。
振り返りは明示的に依頼されたときに行う。候補を残すことは採用を意味しない。恒常的な指示・スキル・ツールへの反映は、ユーザーが採用を指示した範囲で行う。
```

## 使い方

- `$improve-workflow このプロジェクトに改善記録の導線を導入して`
- `$improve-workflow 今回の作業を振り返って。候補がなければ記録不要`
- `$improve-workflow 候補YYYYMMDD-xxxを、次のテスト追加作業だけで試して`
- `$improve-workflow 候補YYYYMMDD-xxxを、このプロジェクトの指示に採用して`
- `$improve-workflow 採用したYYYYMMDD-xxxが今回役立ったか確認して`
- `$improve-workflow YYYYMMDD-xxxの採用を取り消して`

ChatGPT Workでは `$improve-workflow` の代わりにスキルを@指定する。
